# MongoDB → PostgreSQL (Drizzle) conversion conventions

The backend moved from Mongoose/MongoDB to PostgreSQL with Drizzle ORM (postgres-js driver, Supabase-ready pooling).
Hard requirement: **every HTTP API response keeps exactly the same JSON shape and semantics as before.** The React client must not need changes.

## Where things live
- Schema: `src/database/schema.ts` (all tables; read its header comment). TS property names == old Mongoose field names.
- DB handle: `import { db, type DbOrTx, type Transaction } from "../../database/connection.js";`
- Tables: `import { users, organizations, ... } from "../../database/schema.js";` Enum constants (`COMMITMENT_STATUSES`, `VISIT_OUTCOMES`, `ASSIGNMENT_STATUSES`, `RECOVERY_PRIORITIES`, `FILE_PURPOSES`, `EMPLOYMENT_TYPES`, `PAYROLL_STATES`, ...) and JSONB types are exported from schema.ts too.
- Operators: `import { and, or, eq, ne, gt, gte, lt, lte, inArray, notInArray, isNull, isNotNull, ilike, asc, desc, sql, count, sum, arrayContains, arrayOverlaps } from "drizzle-orm";`
- Helpers: `src/common/utils/db.ts` → `isDuplicateKey`, `isForeignKeyViolation`, `escapeLike`, `withMongoId`, `isUuid`, `first`.
- `*.model.ts` files are being deleted. Do not import them.

## Identifiers
- Mongo `_id` → `id` (uuid string generated by Postgres). `doc._id.toString()` → `row.id`. `new Types.ObjectId(x)` → `x`. `Types.ObjectId.isValid(x)` → `isUuid(x)`.
- Id columns are plain strings; drop `.toString()`/`.equals()` on ids (`a.equals(b)` → `a === b`).

## Response shape compatibility (most important rule)
- If a function built a DTO (`{ id: doc._id.toString(), ... }`), build the same DTO from the row.
- If it returned a raw Mongoose document / `.lean()` result / spread of a document, the JSON used to contain `_id` (not `id`) — return `withMongoId(row)` (adds `_id`, keeps `id`). `__v` can be dropped.
- Populated references: `.populate("employeeId", "employeeNumber firstName")` replaced the id with an object `{ _id, employeeNumber, firstName }` (or `null` if missing). Reproduce that **exact nested shape including `_id`** using a join or a second `inArray` query + Map. Code that reads populated fields (`doc.employeeId.firstName`) must get the same data.
- Mongoose Maps (`organizations.modules`, `users.modulePermissions`) are now plain JSON objects: `map.get(k)` → `obj[k]`, `map.set(k,v)` → build a new object and update. Serialized JSON is unchanged.
- Timestamp columns return `Date` objects (as Mongoose did). Money columns (`bigint` mode number) return numbers.
- Date/time values **inside JSONB** (punches `checkIn.at`, adjustment `history[].at`, invoice `cancellation.cancelledAt`, payroll `attendanceDays[].checkInAt`, compliance `activationHistory[].changedAt`) are ISO strings. Write `date.toISOString()`; read with `new Date(value)` where arithmetic is needed. JSON output is unchanged.

## Query translation
| Mongoose | Drizzle |
|---|---|
| `Model.find(filter).sort().skip().limit()` | `db.select().from(t).where(and(...)).orderBy(...).limit(n).offset(k)` |
| `findOne` / `findById` | `db.select()...limit(1)` then `rows[0] ?? null` (or `db.query.<table>.findFirst`) |
| `countDocuments(f)` | `db.$count(t, where)` |
| `exists(f)` | `(await db.select({ id: t.id }).from(t).where(...).limit(1)).length > 0` |
| `create(doc)` / `insertMany` | `db.insert(t).values(v).returning()` |
| `updateOne` / `updateMany` | `db.update(t).set({...}).where(...)` |
| `findOneAndUpdate(f, u, { new: true })` | `db.update(t).set(u).where(f).returning()` → `[0] ?? null` (the where clause carries the state guard, so it stays atomic) |
| `upsert: true` | `db.insert(t).values(v).onConflictDoUpdate({ target: [...unique cols], set: {...} }).returning()` |
| `$inc: { x: n }` | `set({ x: sql\`${t.x} + ${n}\` })` |
| `$push` to JSONB array | read-modify-write inside a transaction, or `sql\`${t.col} || ${JSON.stringify([item])}::jsonb\`` |
| `deleteOne` / `findOneAndDelete` | `db.delete(t).where(...).returning()` |
| `distinct("f", filter)` | `db.selectDistinct({ f: t.f }).from(t).where(...)` |
| `{ field: { $in: ids } }` | `inArray(t.field, ids)` — **guard empty arrays** (`ids.length ? inArray(...) : sql\`false\``) |
| `{ arrayField: id }` (array contains) | `arrayContains(t.arrayField, [id])` |
| `{ arrayField: { $in: ids } }` | `arrayOverlaps(t.arrayField, ids)` (guard empty) |
| `$regex: term, $options: "i"` | `ilike(t.col, \`%${escapeLike(term)}%\`)` |
| `{ f: null }` | `isNull(t.f)`; `{ f: { $ne: null } }` → `isNotNull(t.f)` |
| `aggregate([...])` | `select` with `groupBy`, `sum`, `count`; cast sums: `sql<number>\`coalesce(sum(${t.amountMinor}), 0)\`.mapWith(Number)` |
| `doc.save()` after mutation | explicit `db.update(t).set(changedFields).where(eq(t.id, row.id))` |
| `isDuplicateKey` (11000) | `isDuplicateKey` from `common/utils/db.ts` (Postgres 23505) |

Sorting: Mongo sorts `null` first ascending; Postgres sorts nulls last ascending. Use `sql\`... nulls first\`` only where it changes visible behaviour.

## Former embedded arrays (now child tables)
- `payments.allocations[]` → `paymentAllocations` (`paymentId`, `organizationId`, `position`, `invoiceId`, `bucket`, `amountMinor`). Order by `position`. API output still has `allocations: [{ invoiceId, bucket, amountMinor }]`. Query "payments allocating invoice X" → join/`inArray` on `paymentAllocations.invoiceId`.
- `payrollRuns.employees[]` → `payrollRunEmployees`; `payrollRuns.payments[]` → `payrollRunPayments`. Both have `runId`, `organizationId`, `position`. API output must still be a run object with `employees: [...]` and `payments: [...]` arrays in their original element shape (no `id`/`runId`/`organizationId`/`position` keys on elements). Write a `loadRuns(ids)` helper; write children in the same transaction as the run.
- Everything else that was nested stays JSONB on the parent row (see schema types).

## Normalization (Mongoose setters are gone — apply on every insert/update)
Lowercase+trim: `users.email`, `customers.email`, customer `contacts[].email`, `workforceEmployees.email`, `gmailConnections.email`, `gmailEmails.senderEmail/recipientEmail`, `subscriptionPlans.code`.
Uppercase+trim: `customers.gstin`, `workforceEmployees.employeeNumber`, `departments.code`, `compensationComponents.code`, `leaveTypes.code`, `complianceRuleSets.regionCode`.
Trim: other fields that had `trim: true` in the old model (names, notes, remarks, references...). Zod schemas already trim many inputs; keep normalization where the model did it. Lookups by email must lowercase the input (Mongoose did that implicitly through the setter on queries too).

## Transactions
Use `db.transaction(async (tx) => { ... })` for multi-row writes that must be all-or-nothing (payments + allocations + ledger + invoice balances, payroll run + children, org + admin user). Replace manual compensation/rollback code with a transaction when doing so is straightforward; behaviour on success must be identical. Helpers that may run inside a transaction take `executor: DbOrTx = db`.

## Misc
- Defaults are in the schema; omit fields to get them.
- `gmailOAuthStates` had a Mongo TTL index: when consuming a state, require `gt(t.expiresAt, new Date())` and delete expired rows opportunistically.
- `gmailConnections.encryptedRefreshToken` was `select: false`: never include it in responses; select it only where the old code used `.select("+encryptedRefreshToken")`.
- Keep exported function names and parameter lists stable (other modules call them). If a function returned a Mongoose document consumed elsewhere, return the row (same field names, `id` instead of `_id`).
- Do not change routes, Zod schemas (ids are already UUIDs via `objectIdSchema`), business rules, error codes/messages, or audit entries.
